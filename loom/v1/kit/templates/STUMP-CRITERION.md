# Stump criterion and rubric template

For the Loom's attack step when a Loom task is used to test a model [STUMP App. A, D]. Write 20 to 30 criteria before the brief, then write the brief from them.

```
R## · <points> · <class S/C/P/T>
Title: <the outcome in 3-6 words>
Brief words: "<exact quote from the brief>"
Check: <what the grader measures, in which file, how often>
If <measurable miss>[, or <second miss>], this item fails.
```

Trigger kinds: tolerance · counted sample · frame window · shortcut named as an outcome · direction or sign · run gate · repeatability · two outputs agree · stress at extreme inputs.

## Weighting
- 80% or more of points on criteria worth 14 to 25 points; files and naming at 5% or less.
- One sentence of the brief may feed 2 to 4 checks; easy items stay light.

## Seams to aim at (one of each)
A number inside creative work (G1) · a version trap the grader runs (I2) · a spec given as an image (F) · one output checked against another (B1) · a shortcut-killer variant (H) · a packaging kill switch (D5).

## Pre-submit (by script where possible)
- [ ] Every criterion quotes brief words; a script confirms each quote word for word
- [ ] Every number appears in the brief or an image, or follows by stated arithmetic; a script recomputed each
- [ ] Unstated professional norms total 5% of points or less
- [ ] Every trigger has a tolerance and a sampling rule; every reference point is defined
- [ ] Exceptions written in; no requirement impossible at its own range corners (tested headless)
- [ ] No criterion rewards or punishes a method unless the brief asks for it as an outcome
- [ ] Each chain named, so one root error costs one item
- [ ] Version, units, axes, fps, starting state, file names and folder contents stated exactly
- [ ] After each run: read every criterion's reasons; move triggers to the slips seen; rerun 2 to 4 times
